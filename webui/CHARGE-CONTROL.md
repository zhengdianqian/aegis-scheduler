# 充电控制行为规格

适用范围：WebUI / APP 充电页、`webui/src/charge-model.js` 的纯函数状态机、`webui/test/charge-model.test.js` 的沙盒用例。

本次不改 `tempo-core` 与守护代码。页面负责配置、展示与本地一致性判断；真正切断/恢复充电电流必须由守护侧按本规格执行。

## 1. 输入

一次判定使用一份采样 + 一份配置 + 当前时间：

| 输入 | 来源 | 说明 |
|---|---|---|
| `percent` | 电池电量 | 0–100 的整数；读不到时为 `null`，不猜测 |
| `tempC` | 电池温度 | °C；读不到时为 `null` |
| `plugged` | 插电状态 | 守护侧由电源 uevent 判断；页面用电池 `status` 推断：`discharging` = 未插电，其余视为已插电 |
| `stopAt` | 配置 | 停充电量，50–100 |
| `resumeAt` | 配置 | 恢复电量，20–`stopAt-1` |
| `tempStop` | 配置 | 停充温度，20–70 |
| `tempResume` | 配置 | 恢复温度，必须低于 `tempStop` |
| `plan` | 预约侧车 | `{enabled, mode, weekdays, windows}`；见第 7 节 |
| `now` | 本机时间 | 用于预约时段判断与涓流计时，按本地时区 |
| `currentMa` | 电池电流 | 充电电流（mA，带符号按绝对值处理）；读不到时为 `null` |
| `voltageMv` | 电池电压 | 可选；仅在配置了 `fullVoltageMv` 时参与满充判定 |
| `statusFull` | 电池 status | `status == "Full"` 时为 `true`；直接作为满充信号 |
| `fullCurrentMa` | 配置 | 涓流满充电流阈值，默认 100（mA） |
| `fullHoldSeconds` | 配置 | 满充信号持续时间，默认 9（秒）；小于 1 按 1 处理 |
| `fullVoltageMv` | 配置 | 可选满充电压阈值，默认关闭（`null`） |

## 2. 唯一策略开关：由上限派生

不再提供“停充后保持”独立开关。

```
latch_per_plug = (stop_at_percent == 100)
```

- `stop_at_percent == 100`：到达 100% **不停充**，先进入涓流阶段；出现满充证据后才停充并锁存，重新插电才恢复。
- `stop_at_percent` 为 80、90 或其他值：达到上限停充，电量回落到恢复阈值后自动复充。
- 保存配置时页面必须按上式写入 `latch_per_plug`，不把该字段暴露给用户。

满充证据（满足任一即判满，且必须在未被温度/预约强制停充时采集）：

| 证据 | 条件 | 生效方式 |
|---|---|---|
| 电池 status | `status == "Full"` | 立即锁存 |
| 涓流电流 | 电流绝对值 ≤ `fullCurrentMa` | 持续满 `fullHoldSeconds` 后锁存 |
| 满充电压 | `voltageMv >= fullVoltageMv`（仅配置后启用） | 持续满 `fullHoldSeconds` 后锁存 |

默认值对齐原模块 C 实现：电流 < 100 mA、守护 3 秒一拍、连续 3 拍（≈9 秒）。

## 3. 内部状态

| 状态 | 含义 | 置位 / 清除 |
|---|---|---|
| `tempBlocked` | 温度保护已触发 | 温度 ≥ `tempStop` 置位；≤ `tempResume` 清除；中间区间保持 |
| `upperLatched` | 100% 满充锁存 | 仅在 `stopAt=100` 时使用；出现满充证据时置位；重新插电、重启、配置变更时清除。锁存后电量回落到 100% 以下也**不清除** |
| `upperHold` | 普通上限保持 | 仅在 `stopAt≠100` 时使用；电量 ≥ `stopAt` 置位；≤ `resumeAt` 清除；中间区间保持 |
| `trickle` | 是否处于涓流阶段 | `stopAt=100`、电量 ≥100、未锁存、且未被温度/预约阻止时为 true |
| `trickleSince` | 满充信号起始时间 | 首次满足满充信号时记录 `now`；信号中断、被温度/预约阻止、拔插、重启、配置变更时清空 |
| `armed` | 100% 锁存是否已武装 | 电量低于 `stopAt` 时为 true；锁存后为 false；重新插电 / 重启 / 配置变更时按当前电量重算 |
| `stopped` | 上一次输出是否为停充 | 用于区分 `stop` 与 `hold`、`resume` 与 `none` |
| `lastPlugged` | 上一次插电状态 | 用于识别“拔出 → 重新插电”事件 |
| `lastPercent` | 上一次电量 | 用于识别 100% 的跨线时刻 |
| 上次阈值 | `stopAt/resumeAt/tempStop/tempResume/latchPerPlug/fullCurrentMa/fullHoldSeconds/fullVoltageMv` | 用于识别配置变更 |

## 4. 单次判定顺序

1. **未插电**：清除全部保持/锁存与涓流计时，输出“允许充电”，动作 `none`。未插电时不做充电控制。
2. **重新插电 / 重启 / 配置变更**：清除 `upperLatched`、`upperHold`、`tempBlocked`、`trickleSince`，并按当前电量重算 `armed`；随后继续按本次采样判定。
3. **温度**：按第 3 节滞回更新 `tempBlocked`。
4. **预约**：按第 7 节计算当前是否在允许时段内（用于判断满充证据是否可信）。
5. **上限 / 涓流**：
   - `latch_per_plug=true`：电量低于 `stopAt` 时 `armed=true`、`trickleSince` 清空；电量 ≥ `stopAt` 且未锁存时进入涓流，按第 2 节满充证据判定：
     - `statusFull=true` → 立即 `upperLatched=true`；
     - 电流/电压满充信号持续 ≥ `fullHoldSeconds` → `upperLatched=true`；
     - 信号中断则清空 `trickleSince` 重新计时；
     - 温度保护或预约时段外导致的停充不算满充证据，`trickleSince` 清空。
   - 锁存后即使电量回落到 100% 以下也不自动复充，直到重新插电 / 重启 / 配置变更。
   - `latch_per_plug=false`：电量 ≥ `stopAt` 时 `upperHold=true`；电量 ≤ `resumeAt` 时 `upperHold=false`；中间区间保持原状态。
6. **组合**：
   - 停充条件取“或”：温度保护、100% 满充锁存、普通上限保持、预约时段外，任一成立即停充。
   - 恢复条件取“与”：以上条件必须全部解除才允许充电。

## 5. 输出与优先级

```json
{
  "allowCharge": false,
  "action": "stop | hold | resume | none",
  "primary": "temp_high | full_latch | upper_bound | plan_window | null",
  "reasons": ["temp_high", "upper_bound", "plan_window"],
  "trickle": true,
  "phase": "charging | trickle | stopped | unplugged"
}
```

停充原因固定排序：

```
温度保护 > 100% 满充锁存 > 普通上限 > 预约时段外
```

- 多个条件同时成立时全部列出，`primary` 取第一个。
- 动作语义：`stop` 从充电转为停充；`hold` 原本已停充且继续停充；`resume` 从停充转为充电；`none` 状态未变化。
- `phase` 仅用于展示：`trickle` 表示正在涓流（此时 `allowCharge=true`、无停充原因），`charging`、`stopped`、`unplugged` 对应其他状态。
- 页面显示“本模块已停充”只在 `allowCharge=false`、实际未充电、且电池状态不是 `discharging` 时成立，避免把拔线误报成停充。

## 6. 关键边界

### 6.1 100% 涓流至满充后停充

- 到达 100% 时**不停充**，进入涓流阶段（`phase=trickle`，`allowCharge=true`，无停充原因）。
- 只有出现第 2 节的满充证据才锁存停充：
  - `status=Full` 立即锁存；
  - 电流绝对值 ≤ `fullCurrentMa` 持续 ≥ `fullHoldSeconds` 锁存；信号中断立即重新计时；
  - 配置了 `fullVoltageMv` 时，电压 ≥ 阈值同样需要持续满时长。
- 满充证据必须在“未被温度保护、未被预约时段阻止”时采集；被强制停充期间电流自然降低，不能算作满充。
- 三项数据（电流、电压、status）都读不到时不做满充判断，保持涓流，避免误停。
- 锁存后电量回落到 99、95 都**不**恢复充电，必须重新插电（或重启/改配置）才恢复。
- 重新插电视为新会话：清除锁存与涓流计时；若插电时已是 100%，重新进入涓流，需重新满 `fullHoldSeconds` 才停充；若电池已报 Full 则立即停充。
- 重启不保留锁存：重启时已是 100% 从涓流开始；重启时电量为 85% 且上限 80%，按普通上限判定为停充。
- 配置从 100% 改为 80/90：清除锁存与涓流计时，按当前电量重新判定；当前电量仍高于新上限则继续停充，回落到恢复阈值后复充。
- 涓流中把上限改回 100% 且电量仍为 100%：重新进入涓流，重新计时。

### 6.2 普通上限

- 80% 上限、70% 恢复：79 允许；80 停充；75、71 保持停充；70 恢复；69 继续充电。
- 90% 上限、80% 恢复：89 允许；90 停充；85 保持；80 恢复。
- 重新插电、重启、配置变更会清除普通上限的保持状态，按当前电量重新判定。

### 6.3 温度

- 达到 `tempStop` 停充；回落到 `tempResume` 恢复；两者之间保持停充。
- 温度保护与预约、上限同时成立时，温度优先展示，但所有条件都保持；温度恢复后，其他条件仍可继续阻止充电。

### 6.4 插拔 / 重启 / 配置变更

| 事件 | 处理 |
|---|---|
| 拔出 | 清除全部保持/锁存与涓流计时，不做充电控制 |
| 重新插电 | 清除全部保持/锁存与涓流计时，按当前电量重算；100% 重新进入涓流 |
| 重启 | 内部状态从空开始；不沿用上次锁存或涓流计时，按当前采样重新判定 |
| 配置变更 | 清除保持/锁存与涓流计时，按新阈值与当前采样重新判定 |
| 涓流中拔出 | 退出涓流；重新插电后从 0 开始累计满充时长 |
| 涓流中温度超限 | 温度优先停充，涓流计时清零；温度恢复后重新进入涓流并重新计时 |
| 涓流中退出预约时段 | 立即停充，涓流计时清零；重新进入时段后恢复涓流并重新计时 |
| 涓流中改上限为 80/90 | 立即按新上限停充；改回 100 且电量为 100 时重新进入涓流 |

## 7. 预约时段

- `enabled=false`、无有效时段、无可用星期：不限制充电。
- 有效时段为 `HH:MM`；`end == start` 无效；`end < start` 表示跨零点；最多 6 段。
- **跨零点时段归属开始日**：周一 23:00–周二 07:00 属于周一。
  - 自定义只选周一时，周二 02:00 仍允许充电；
  - 周二 23:30 不属于周一，应停充；
  - 自定义只选周日时，周一 02:00 仍允许充电。
- 结束边界 `07:00` 不算在时段内；开始边界 `23:00` 算在时段内。
- 页面同时显示“当前是否允许充电”和下一切换节点（如“今天 23:00 恢复充电（11 小时后）”）。

## 8. 守护侧落地要求（行为规格）

守护侧必须实现以下语义，页面逻辑与此保持一致：

1. 读取 `[charge]` 配置与 `charge_plan.json`，配置变化后重新判定，不使用旧缓存。
2. 在电源 uevent、配置变化、时段边界到达时判定；不新增周期性轮询。
3. 识别拔出 → 重新插电的边沿，清除锁存；未插电时不做控制。
4. 仅在 `stop_at_percent == 100` 时启用涓流与锁存：到 100% 继续涓流，按满充证据（status Full / 电流 ≤ `full_current_ma` 持续 `full_hold_seconds` / 可选电压）才停充；80/90 等阈值按滞回复充。
5. 涓流计时使用单调时钟；温度/预约导致的停充期间不得采集满充证据，恢复后重新计时。
6. 温度保护独立滞回，可与上限/预约叠加；恢复必须等所有阻止条件解除。
7. 预约时段按开始日归属星期，跨零点时段在次日凌晨继续生效。
8. 重启后不恢复旧锁存与涓流计时；按当前电量/温度/status 重新判定。
9. 停充与恢复只改变充电使能节点，不修改用户配置。

## 9. 当前实现差距（本次不修改守护）

- `tempo-core` 现有 `ChargeGovernor` 已实现温度滞回与上限滞回，但 `latch_per_plug` 仍是全局配置项；页面通过派生值把它约束为“仅 100% 为 true”。
- 守护尚未实现“到 100% 后涓流至满充再停”的判定，也没有读取满充电流/电压/status；本规格与页面模型已就绪，等守护侧接入。
- 守护尚未读取 `charge_plan.json`，预约时段目前由页面计算并展示；实际按时段停充需守护按第 8 节接入。
- 电源快照未直接暴露 `plugged`；页面用 `battery.status` 推断，守护侧应以 uevent 为准。
