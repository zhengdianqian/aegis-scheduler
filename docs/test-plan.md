# Tempo 测试与验收计划

- 版本：v1.0（P1）
- 适用：`tempod` / `tempowerd` / WebUI / APP
- 量化口径与 [behavior-spec.md](behavior-spec.md) §9 一致

## 1. 阶段门禁

| 阶段 | 内容 | 门禁 | 是否需用户确认 |
|---|---|---|---|
| P1 | 骨架、纯控制器、档案生成、单测 | `cargo test --workspace` 全绿；档案与真机拓扑一致；不写 sysfs | 否 |
| P2 | 事件源（eBPF/触摸/帧/屏幕/前台/充电/热）只读接入 | 事件计数正确；空闲 10min 无周期唤醒；仍不写 sysfs | 否 |
| P3 | 受控写入 cpufreq（先 sandbox 目录 + 单簇） | 写失败可回滚；静默/触摸/帧路径符合规格；真机可回退 | **刷入模块或重启设备前必须确认** |
| P4 | 真机 A/B、功耗与帧稳定性 | 静态 ≤0.90× 基线；日常/视频 ≤1.00×；游戏 jank ≤基线 | 刷入/重启前确认 |
| P5 | WebUI / APP | 只通过 `tempoctl` 读取同一数据模型；不常驻、不轮询 | 安装 APK 前确认 |

## 2. P1 自检（已执行）

- `cargo test --workspace`：12 个单元测试 + 9 个集成测试通过。
- 真机只读生成 `profiles/babylon.toml`：
  - 3 簇：`[0,1,2]` / `[3,4,5,6]` / `[7]`
  - min/max：`307200..2016000` / `499200..2803200` / `595200..3360000`
  - capacity：`266 / 811 / 1024`，角色 `efficiency / balanced / prime`
  - 频率表来自 `scaling_available_frequencies`，含真实档位
- `tempoctl decide` 离线回放：低负载静默在 260ms 内落到三簇最低频；`next_deadline=None`。
- `tempod --check`：只读摘要，`scheduler_writes=false`。

## 3. P2 只读观测

### 3.1 事件正确性

| 检查 | 方法 | 通过标准 |
|---|---|---|
| eBPF 可用性 | 探测 `sched_switch` tracepoint 与前台帧 uprobe | 可用则记录；不可用则上报 `scheduler_disabled`，不降级轮询 |
| 需求事件 | 采集 5min 混合负载，统计事件数与 CPU 占用 | 事件只在累计运行量/空闲边沿产生；探针线程 CPU <0.5% 单核 |
| 触摸 | 滑动/点击各 20 次 | 每次都有抬频事件；无 timeout 轮询 |
| 屏幕/充电/热 | 息屏/亮屏、插拔、加热各 5 次 | uevent 均被接收；无固定间隔读取 |
| 前台切换 | 10 次应用切换 | 旧负载清零，新前台暖启动 |

### 3.2 空闲唤醒

- 静默 + 息屏各 10min，外部每 30s 采样一次 `top`/`dumpsys cpuinfo`（外部采样不计入模块）。
- 通过：进程唤醒 <0.2 次/s，CPU <0.2% 单核，无 `timerfd` 周期唤醒。

## 4. P3 受控写入（需确认）

1. 先在 `/data/local/tmp` 的 sandbox 频率节点验证写入/回滚，不触碰真实 cpufreq。
2. 单簇（efficiency）最短路径验证：屏幕关 → min；触摸 → 抬频；150ms → 回落。
3. 再开放三簇；任何写失败立即回滚上一安全上限并上报。
4. 提供一键恢复：删除模块目录并重启，或 `tempoctl` 恢复默认上限。
5. **刷入模块/重启设备前**向用户确认，附上变更清单与回滚步骤。

## 5. P4 真机 A/B（功耗与静态）

### 5.1 环境

- 同机同 ROM，飞行模式，亮度固定 30%，室温 24±2°C，电池 80% 起测。
- 每场景 30min；顺序随机；每场景 3 次；取中位数。
- 基线：发布前安装的参考模块（用户当前配置）；实验组：Tempo。
- 外部能耗计量优先（USB 功率计）；无外部计量时用 `dumpsys batterystats` 库仑计数，并同步记录 `time_in_state`。

### 5.2 场景与指标

| 场景 | 操作 | 主指标 | 通过标准 |
|---|---|---|---|
| 静态阅读（一级） | 小说类 App 固定页面，屏幕常亮，不触摸 | %/h、mAh、各簇 min 频占比、抬频次数 | 能耗 ≤0.90× 基线；min 频占比 ≥95%（首 60s 除外）；无 >100ms 的抬频 |
| 日常滑动 | 桌面/信息流连续滑动 30min | %/h、换档次数、jank | 能耗 ≤1.00×；1s 内换档 ≤4 次；jank ≤基线 |
| 视频 | 本地 1080p 30fps 播放 | %/h、掉帧 | 能耗 ≤1.00×；掉帧 ≤基线 |
| 游戏 | 固定画质/帧率 20min | %/h、jank、温度 | jank ≤基线；温度 ≤基线+2°C |

### 5.3 静态专项

- 从触摸结束/最后一次帧超时到 min 频：≤150ms（P95），无 >300ms 尾部。
- 连续 10min 负载不变：高于 min 的连续区间 0 个 >100ms；抬频 ≤1 次/10min 且可解释。
- 记录 `time_in_state` 首 60s 稳定期后统计，避免启动瞬态污染。
- 若 min 频占比不足：先查是否有后台前台化、帧超时或热上限；不得通过提高静默阈值“刷指标”。

### 5.4 防测量偏差

- 关闭自动亮度、同步、定位、后台更新；固定 App 版本与页面。
- 基线/实验组交替各 3 次，避免电池老化单向偏差。
- 采样脚本与解析在主机侧运行；模块内不增加任何测量线程。
- 所有原始数据与命令写入 `tests/bench/` 之外的临时目录，不进入模块包。

## 6. P5 WebUI / APP

- 只调用 `tempoctl`（UDS / CLI），不直接写 sysfs。
- APP 不常驻、不注册周期任务；WebUI 仅在管理器页面打开时运行。
- 校验：配置读写、状态展示、错误提示与 CLI 输出一致；无网络权限（除本地）。

## 7. 失败处理

- 任一阶段出现卡顿、过热、无法回滚 → 立即停止写入，恢复上一安全上限，保留日志。
- eBPF/内核能力不足 → 禁用调度并上报，不尝试降级采样。
- 档案与 live 拓扑不一致 → 重新生成档案；仍不一致则禁用调度。
